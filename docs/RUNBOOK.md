# دليل التشغيل — HBS حلول الغد

هذا الدليل لمن يشغّل hrhbs.com: النشر، الأسرار، المهام الدورية، الاحتفاظ بالبيانات، النسخ الاحتياطي، والتراجع. وصف المنتج والميزات في [README.md](../README.md).

القاعدة الأولى في كل ما يلي: **الترحيلات تُطبّق بـ migrate فقط. لا drizzle-kit push على الإنتاج أبدًا.**

## 1. المكوّنات في الإنتاج
- **الموقع والبوابة:** artifacts/hbs-solutions مبني بـ Vite ويُخدم من server.mjs (ملفات ثابتة مسبقة التصيير، ترويسات أمان، ضغط مسبق .br/.gz).
- **خادم API:** artifacts/api-server (Express) على منفذ منفصل، يُوجَّه إليه /api و/api/__clerk من المستضيف. يشغّل المهام الدورية داخل العملية نفسها.
- **قاعدة البيانات:** PostgreSQL واحدة عبر DATABASE_URL، مخططها من ترحيلات lib/db/migrations.
- **التخزين:** مرفقات الطلبات في Replit App Storage عبر PRIVATE_OBJECT_DIR.
- **الخدمات الخارجية:** Clerk (الهوية)، SMTP (البريد)، WhatsApp Business Cloud API، ميسّر (السداد)، واثق (السجل التجاري)، OpenAI وAnthropic (القراءة الآلية والمساعد).

## 2. النشر

### قبل النشر
1. الفرع main أخضر في GitHub Actions (typecheck، codegen بلا فرق، الترحيلات تطابق المخطط، الاختبارات، البناء).
2. إن كان الدمج يضيف ترحيلًا جديدًا: اقرأ ملف SQL وتأكد أنه إضافي (أعمدة جديدة، جداول جديدة، فهارس) ولا يعيد كتابة جدول كبير. خذ نسخة احتياطية من القاعدة قبل تطبيقه.
3. إن كان الدمج يضيف متغير بيئة جديدًا (راجع artifacts/api-server/.env.example وartifacts/hbs-solutions/.env.example): اضبطه في مدير الأسرار قبل إعادة التشغيل.

### خطوات النشر (الأمر الذي نعطيه لوكيل Replit)
انسخ النص التالي كما هو إلى Replit Agent عند كل نشر؛ هو يصف التسلسل الوحيد المسموح به:

```
انشر آخر نسخة من الفرع main من GitHub بالترتيب التالي دون أي خطوة إضافية:
1. git pull للفرع main.
2. pnpm install --frozen-lockfile.
3. pnpm --filter @workspace/api-spec run codegen.
4. pnpm run typecheck.
5. pnpm --filter @workspace/db run migrate (لا تستخدم drizzle-kit push إطلاقًا، ولا تعدّل المخطط يدويًا).
6. pnpm --filter @workspace/api-server run build.
7. PORT=<منفذ الموقع> BASE_PATH=/ pnpm --filter @workspace/hbs-solutions run build.
8. أعد تشغيل خادم API ثم خادم الموقع.
9. تحقق أن /api/healthz يعيد 200 وأن الصفحة الرئيسية و/services و/sign-in تفتح.
لا تغيّر أي سر أو متغير بيئة، ولا إعدادات Clerk، ولا تنشئ ملفات .env، ولا تشغّل سكربتات أخرى.
```

ملاحظات:
- migrate على قاعدة أُنشئت سابقًا بـ push يفشل دون تغيير حتى يُسجَّل خطّها الأساسي مرة واحدة بـ baseline أو adopt (التفاصيل في README «قاعدة البيانات»).
- scripts/post-merge.sh (التثبيت، codegen، فحص المخطط للقراءة فقط) خطوة Replit الاختيارية بعد الدمج؛ لا تستبدل migrate ولا تكتب في القاعدة.
- خادم API يرفض البدء دون PORT، ويبدأ المهام الدورية بعد الاستماع.
- عند إعادة التشغيل يستقبل الخادم SIGTERM فيغلق المنفذ، ويُنهي تدفقات الإشعارات الحية، ويترك المهمة الجارية تكتمل بحد 10 ثوانٍ. المتصفحات تعيد الاتصال تلقائيًا.

### بعد النشر
- افتح /notifications في حساب مكتب وتأكد أن التدفق الحي متصل (الشارة لا تعرض «غير متصل» بعد ثوانٍ).
- إن غُيّر قالب واتساب أو رقم المكتب: أرسل رسالة تجريبية من صندوق واتساب المكتب.
- راجع سجلات الخادم لأول دقائق بحثًا عن error.

## 3. الأسرار ومتغيرات البيئة
- الجدول الكامل بالأسماء والمعاني في README «متغيرات البيئة»، والنسخة القابلة للنسخ في ملفي .env.example داخل كل artifact.
- تُضبط في مدير الأسرار لدى المستضيف فقط. لا تُكتب في الملفات ولا في Git ولا في رسائل الدردشة مع الوكيل. ملفات .env و.env.* متجاهلة في .gitignore ما عدا .env.example.
- **المتغيرات التي تبدأ بـ VITE_** تدخل حزمة المتصفح وتصبح عامة؛ لا تضع فيها سوى المفتاح العام لـ Clerk وعنوان الوكيل.
- **ما يحدد سلوكًا أمنيًا:** HBS_OFFICE_EMAIL (من هو المالك)، CLERK_SECRET_KEY، WHATSAPP_APP_SECRET (توقيع الوارد وتوثيق الأرقام)، MOYASAR_WEBHOOK_SECRET، VAPID_PRIVATE_KEY. تغيير أي منها يستلزم إعادة تشغيل خادم API.
- **تدوير الأسرار:** أصدر المفتاح الجديد لدى المزوّد، اضبطه، أعد تشغيل الخادم، ثم ألغِ القديم. لمفاتيح VAPID: تغييرها يُبطل اشتراكات الدفع الفوري الحالية وسيعيد المتصفح الاشتراك عند الزيارة التالية.
- **رقم المكتب:** OFFICE_WHATSAPP_NUMBER يجب ضبطه في أي بيئة غير الإنتاج حتى لا تصل الرسائل التجريبية إلى الرقم الحقيقي.
- بيئات المعاينة والتجربة: لا تعطها DATABASE_URL الإنتاج ولا مفاتيح واتساب أو ميسّر الحقيقية.

## 4. Webhooks الواردة
| الخدمة | المسار | التحقق |
|---|---|---|
| ميسّر | https://hrhbs.com/api/payments/moyasar/webhook | MOYASAR_WEBHOOK_SECRET، ثم جلب الفاتورة من ميسّر ومطابقة المبلغ والعملة |
| واتساب (Meta) | https://hrhbs.com/api/webhooks/whatsapp | WHATSAPP_VERIFY_TOKEN عند التسجيل، توقيع WHATSAPP_APP_SECRET لكل تسليم، رفض المكرر |

إذا توقف أحدهما: السداد يُلتقط بمهمة المطابقة كل 30 دقيقة للصفحات المفتوحة؛ رسائل واتساب الواردة لا تُلتقط لاحقًا، فأعد تسجيل الـWebhook في لوحة Meta.

## 5. المهام الدورية
كلها داخل عملية خادم API، تبدأ بعد الاستماع، وتعيد جدولة نفسها بعد اكتمال كل دورة. المطالبات ذرّية في القاعدة، فتشغيل نسختين من الخادم آمن (لا رسائل مكررة) وإن تكرر بعض العمل. حدود المعدّل لكل IP وخريطة مستمعي SSE محلية لكل نسخة.

| المهمة | الفاصل | التأثير إذا توقفت |
|---|---|---|
| تنظيف المرفقات | 15 دقيقة | تبقى الرفعات غير المكتملة ومرفقات الطلبات المكتملة أكثر من 90 يومًا |
| تنبيهات الوثائق والتجديد التلقائي | ساعة | لا تصل تنبيهات 30/7/1 ولا تُفتح طلبات التجديد |
| مطابقة السداد | 30 دقيقة | سداد فاته الـWebhook لا يُسجَّل |
| تذكير الفواتير | يوم | لا بريد بعد 3 و7 أيام |
| الاشتراكات | يوم | لا فواتير تجديد ولا انتقال إلى متأخر/ملغى |
| الإشعارات المحجوزة | 10 دقائق | ما حُجز لساعات الهدوء والملخص لا يُرسل |
| التنظيف اليومي | يوم | تتراكم الإشعارات المقروءة ورسائل واتساب واشتراكات الدفع الفاشلة |

لا يوجد مجدول خارجي؛ إعادة تشغيل الخادم تعيد كل المهام من دورتها الأولى.

| البيانات | المدة | الآلية |
|---|---|---|
| مرفقات الطلبات | 90 يومًا بعد اكتمال الطلب | تنظيف المرفقات؛ الحذف مسجّل في التدقيق |

| اشتراكات الدفع الفوري الفاشلة | 30 يومًا من أول فشل | التنظيف اليومي |

| الأرشيف القديم (hbs_legacy_records) | دون حذف تلقائي | أرشيف مكتب مستقل، غير مرتبط بحسابات العملاء |

## 7. النسخ الاحتياطي — تنبيه
- النسخ الاحتياطي للقاعدة من مسؤولية المستضيف (نسخ Replit/Neon) وليس من هذا المستودع؛ تأكد أنه مفعّل وأنك تعرف كيف تستعيده قبل أن تحتاجه.
- مرفقات الطلبات في App Storage **خارج** نسخة القاعدة؛ سجل المرفقات في القاعدة يشير إلى ملفات في التخزين، فاستعادة القاعدة وحدها دون التخزين تترك مراجع إلى ملفات مفقودة.
- خذ نسخة يدوية قبل: أي ترحيل، أي baseline أو adopt، أي استيراد كبير من Excel أو من الأرشيف القديم، وأي تدوير لمفاتيح ميسّر.
- اختبر الاستعادة على نسخة منفصلة؛ لا تشر خادم الإنتاج إلى قاعدة مستعادة قبل التأكد من اكتمالها.

## 8. التراجع (rollback)
- **الشيفرة:** أعد نشر الوسم أو الدمج السابق بالخطوات نفسها في القسم 2. لا تعدّل الملفات يدويًا على الخادم.
- **الترحيلات لا تُعكس تلقائيًا.** الترحيلات في هذا المستودع إضافية، فالنسخة السابقة من الشيفرة تعمل مع مخطط أحدث. لا تحذف أعمدة أو جداول يدويًا، ولا تستخدم push «لمطابقة» المخطط مع الشيفرة القديمة؛ push يقترح حذف الجداول القديمة المحتفظ بها.
- إذا فشل ترحيل أثناء النشر: يتوقف migrate دون تطبيق الملف الفاشل (كل ملف في معاملة). أصلح السبب في فرع، وادمجه، وأعد النشر. لا تسجّل الترحيل كمطبّق يدويًا.
- إذا لزم الرجوع إلى نسخة قاعدة بيانات: استعد النسخة على قاعدة جديدة، وجّه DATABASE_URL إليها، وأعد تشغيل الخادم، ثم شغّل migrate لتطبيق ما بعد النسخة. ما حدث بعد وقت النسخة (طلبات، رسائل، سدادات) يُفقد؛ راجع ميسّر وواتساب يدويًا لتلك الفترة.
- بعد أي تراجع: افحص /api/healthz، وسجلات الخادم، والتدفق الحي للإشعارات.

## 9. عند الأعطال الشائعة
- **الخادم لا يبدأ:** غالبًا PORT أو DATABASE_URL غير مضبوط، أو قاعدة موجودة لم تُسجَّل بـ baseline.
- **المكتب يرى 403 بعد النشر:** تحقق من HBS_OFFICE_EMAIL ومن أن بريد المالك مؤكّد في Clerk. صلاحية الموظف تسقط خلال دقيقة إذا أُلغي تأكيد بريده.
- **البريد لا يصل:** SMTP_HOST وSMTP_USER وSMTP_PASS كلها مطلوبة؛ الخادم يسجّل رمز خطأ SMTP دون النص.
- **واتساب لا يُرسل:** يشترط WHATSAPP_ACCESS_TOKEN وWHATSAPP_PHONE_NUMBER_ID وWHATSAPP_TEMPLATE_NAME، ورقم عميل موثّقًا ومفعّلًا. توثيق الأرقام يشترط WHATSAPP_APP_SECRET.
- **الدفع الفوري معطل:** مفاتيح VAPID الثلاثة مطلوبة معًا؛ يقبل الخادم اشتراكات https من خدمات الدفع المعروفة فقط.
- **السداد الإلكتروني معطل:** MOYASAR_SECRET_KEY غير مضبوط؛ يبقى تسجيل السداد اليدوي من المكتب.
- **التدفق الحي يتقطع:** المتصفح يعيد الاتصال بتراجع متدرّج حتى 30 ثانية ويستطلع دوريًا أثناء الانقطاع؛ تحقق من أن الوكيل أمام /api لا يقطع الاتصالات الطويلة.
